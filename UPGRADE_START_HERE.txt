================================================================================
                          WHAT IS UPGRADE?
================================================================================

A mechanism to deploy new contract code to the SAME contract address without
redeploying the entire contract. All data, configuration, and state are
automatically preserved.

BEFORE UPGRADE              AFTER UPGRADE
Address: CAA3XNSN7V3DZQV5  → Address: CAA3XNSN7V3DZQV5 (SAME!)
Code: v1.0.0               → Code: v1.1.0 (NEW!)
Data: [all streams...]     → Data: [all streams...] (PRESERVED!)

================================================================================
                         QUICK START (5 MINUTES)
================================================================================

1. BUILD NEW CODE
   $ cd contracts/stream
   $ cargo build --target wasm32v1-none --release

2. GET HASH
   $ sha256sum target/wasm32v1-none/release/sorostream_stream.wasm
   Output: 3f4a5b2c... (this is your WASM hash)

3. TEST ON TESTNET
   $ stellar contract invoke \
       --network testnet \
       --id <TESTNET_CONTRACT> \
       -- upgrade \
       --new_wasm_hash <HASH>

4. UPGRADE MAINNET
   $ stellar contract invoke \
       --network public \
       --id <MAINNET_CONTRACT> \
       -- upgrade \
       --new_wasm_hash <HASH>

5. VERIFY
   $ stellar contract invoke \
       --network public \
       --id <MAINNET_CONTRACT> \
       -- get_version
   Output: 1.1.0 (version changed!)

================================================================================
                            KEY CONCEPTS
================================================================================

1. ADMIN-ONLY
   Only the contract admin can call upgrade
   Requires: Admin's private signing key
   Verification: Cryptographic signature

2. STATE PRESERVED
   All contract data survives the upgrade
   ✅ Admin address
   ✅ All streams
   ✅ Fee configuration
   ✅ All indices
   ✅ Audit log
   ✅ ALL user data

3. ATOMIC OPERATION
   Upgrade succeeds completely or fails completely
   No partial state corruption possible
   Safe to retry if it fails

4. NO REDEPLOYMENT
   Contract address stays the same
   No integration breakage
   Users see no disruption

5. WASM HASH
   SHA256 hash of the new contract code
   Uniquely identifies the code
   Submit this to upgrade() function

                            QUICK REFERENCE

WHAT YOU'RE DOING:
  Replacing contract bytecode at same address

WHO CAN DO IT:
  Only the contract admin

HOW IT WORKS:
  1. Build new WASM
  2. Calculate SHA256 hash
  3. Call upgrade(hash) with admin signature
  4. Soroban SDK replaces bytecode
  5. New code runs with old data

WHAT HAPPENS TO DATA:
  Everything is preserved automatically
  No migration needed
  No special steps required

HOW LONG DOES IT TAKE:
  Seconds to call
  5 seconds for confirmation
  State transfer is instant

CAN I ROLLBACK:
  Yes - upgrade to previous WASM
  Keep old binary for this

WHAT IF NEW CODE HAS BUG:
  Rollback to previous version
  That's why you test on testnet first
